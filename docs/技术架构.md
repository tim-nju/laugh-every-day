# LaughEveryDay (天天开心) · 技术架构

## 目标与范围

LaughEveryDay 是专为追求高能量与积极心理状态的用户打造的“每日 10 分钟开心药方”极简高质感 PWA 应用。解决传统娱乐应用无底洞信息流、被动投喂、低质低俗导致看完充满内耗和负罪感的问题。第二期核心演进：
1. **笑点校准与杨波式 One-Liner 引擎**：聚焦脱口秀演员杨波标志性的“冷面一句话神反转（Deadpan Misdirection）”，以极短铺垫、零废话陈述、突发性逻辑与道德逆转（如偷看洗澡经典反差、硬核自嘲、反装逼大实话）作为第一核心笑料爆点，击穿成年人理性防御。
2. **自动化每日猎手与 iCloud 归档（方案B）**：提供本地自动化脚本，每日定时采集、提炼并编排次日 10 分钟专属开心胶囊，产出不可变快照并自动归档至用户个人 iCloud 云端目录（`应用备份/LaughEveryDay/capsules/`），实现内容源源不断且数据全权自持。
3. **原生 PWA 标准支持**：提供标准 Web App Manifest 与 Service Worker 离线缓存，支持在 macOS / iOS / Android 上一键添加至主屏幕（Add to Home Screen），以独立全屏窗口沉浸式运行。
4. **范围边界**：核心运行依然为客户端本地驱动型，自动化猎手脚本运行于本地宿主环境，生成静态 JSON 胶囊供 PWA 读取与离线持久化。

## 技术栈

- **前端核心与 PWA 规范**：纯原生现代 Web 标准（HTML5、CSS3 Variables、Vanilla Modern JavaScript ES2022），支持 Service Worker API（Cache-First / Stale-While-Revalidate 策略）与 Web App Manifest 规范，零外部打包器依赖。
- **媒体与交互动效**：原生 Canvas/SVG（雷达图与五彩纸屑）、HTML5 视频与交互式模拟切片，支持移动端平滑滑动手势与即时触觉反馈。
- **每日猎手与自动化引擎（方案B）**：Python 3.10+ 标准库脚本（`scripts/daily_hunter.py`），负责生成标准化每日开心胶囊并执行 iCloud 同步备份。
- **存储与离线持久化**：客户端 LocalStorage（用户偏好、评分权重、连续打卡历史）加 CacheStorage（PWA 应用壳与离线静态资产），iCloud 统一持久化备份。
- **架构审计**：遵循第二大脑规范，采用根目录 `scripts/check_technical_docs.py` 进行技术架构合规审计。

## 模块与目录

- `index.html`：PWA 主入口，挂载 Manifest 与 Service Worker 注册脚本，包含评测、胶囊、雷达、弹药库四大视图。
- `manifest.json`：PWA 应用清单，配置独立全屏模式、双色主题色、应用图标与启动路径。
- `sw.js`：Service Worker 核心，实现离线缓存拦截、资源版本化与网络兜底策略。
- `styles.css`：高质感视觉系统，提供阳光琥珀与深邃石墨主题、响应式适配与卡片平滑动效。
- `app.js`：主控制器，管理视图切换、10 分钟倒计时流、胶囊播放与交互评分事件。
- `quiz.js`：笑点评测引擎，负责 6 维度笑点测算与动态 Canvas/SVG 雷达图渲染。
- `data.js`：核心素材库，全面升级引入杨波式冷面神转折 One-Liner 题库与多模态笑料。
- `storage.js`：本地状态持久化层，管理偏好画像、打卡记录、收藏夹与权重调整。
- `scripts/daily_hunter.py`：方案B每日猎手引擎，自动化组装 10 分钟胶囊并同步归档至 iCloud。
- `scripts/check_technical_docs.py`：项目技术文档合规网关脚本。
- `docs/技术架构.md`：现行技术架构规范文档。
- `docs/技术文档同步.json`：架构同步与完整性校验记录。
- `docs/evidence/`：真实浏览器自动化验收截图与执行回执。

## 数据模型

系统包含五个核心实体，规范胶囊组装、用户雷达画像与 iCloud 归档快照：
1. **笑点评测题目实体（QuizQuestion）**：包含题目唯一标识 id、流派分类 category（特含 `deadpan_wit` 与 `self_deprecation`）、微样本正文 content、关键反转包袱 punchline。
2. **用户笑点雷达画像（HumorProfile）**：包含评测时间戳 calibratedAt、各流派权重 weights、主次偏好标签与专属称号 title（如“冷面神转折笑匠”）。
3. **单条笑料实体（LaughItem）**：包含全局唯一编码 id、流派 category、内容形式 type（文字 One-Liner、神图漫画、短视频）、标题 title、正文 body、反转包袱 punchline、预估阅读时长 durationSec。
4. **今日开心胶囊实体（DailyCapsule）**：包含日期标记 date、目标总秒数 totalDurationSec（600秒）、内容条目序列 items、播放游标 currentIndex、完成标记 completed。
5. **iCloud 归档快照契约（CapsuleArchiveRecord）**：包含胶囊生成时间 generatedAt、归档路径 icloudPath、内容条数 itemCount、条目指纹校验和 checksum。

```typescript
interface LaughItem {
  id: string;
  category: HumorCategory;
  type: 'text' | 'image' | 'video';
  title: string;
  body: string;
  punchline?: string;
  durationSec: number;
  authorOrSource?: string;
  tags: string[];
}

interface DailyCapsule {
  date: string;
  totalDurationSec: number;
  items: LaughItem[];
  currentIndex: number;
  completed: boolean;
  timeSpentSec: number;
}
```

## 接口与契约

1. **Service Worker 生命周期契约**：
   - `sw.js` 监听 `install` 事件预缓存核心静态应用壳；
   - 监听 `activate` 事件清理旧版本缓存；
   - 监听 `fetch` 事件采用 Cache-First 策略优先命中本地快速加载，离线无缝可用。
2. **方案B每日猎手脚本契约**：
   - 执行入口：`python3 scripts/daily_hunter.py --date YYYY-MM-DD --archive`
   - 输入参数：目标日期与是否归档至 iCloud 标志；
   - 输出产物：在应用目录写入 `daily_capsule.json`，并在 iCloud 目录 `/Users/chuangwen/Library/Mobile Documents/com~apple~CloudDocs/应用备份/LaughEveryDay/capsules/capsule-YYYY-MM-DD.json` 生成不可变快照备份。
3. **笑点反馈微调契约**：
   - `StorageService.updateWeights(category, delta)`：对当前分类执行权重增减并持久化，即时重塑次日胶囊筛选概率分布。

## 关键流程

1. **PWA 安装与离线就绪流程**：用户使用手机 Safari 或桌面 Chrome 打开 -> 浏览器解析 `manifest.json` -> 触发 `beforeinstallprompt` 或提示“添加到主屏幕” -> 后台静默激活 `sw.js` 缓存核心资产 -> 离线环境下依然秒开。
2. **方案B自动化每日采集与 iCloud 归档流程**：本地定时触发或手工调用 `daily_hunter.py` -> 引擎根据用户最新笑点画像偏好，从杨波式 One-Liner、真实神抓拍与脱口秀视频切片中提取 10 分钟配额组合 -> 校验时长与流派分布 -> 写入本地与 iCloud 快照目录 -> 唤醒前端直接加载。
3. **杨波式冷面暴击体验流**：用户进入今日胶囊 -> 环节一进入“冷面连环炮”（连续 5-8 条极短铺垫与炸裂反转，每条仅 15 秒，快速释放高密度多巴胺） -> 环节二进入高能图漫 -> 环节三进入脱口秀高能切片 -> 10分钟完结打卡。

## 技术决策

1. **为什么选择杨波式 One-Liner 而不是传统相声小品或长篇段子？**
   - 决策日期：2026-11-13。
   - 理由：用户明确反馈“目前还没看到让我笑出声的，喜欢杨波尤其是偷看洗澡”。高认知用户对冗长煽情的套路免疫，One-Liner 具有极高信息密度与突发性反转冲力，是真正打破理性防线产生生理性爆笑的最优武器。
2. **为什么每日内容快照归档在 iCloud（方案B）？**
   - 决策日期：2026-11-13。
   - 理由：兼顾海量内容与数据掌控权。通过本地脚本生成并在 iCloud 自动留存快照，既不依赖外部闭源付费服务，又能跨 Mac 和 iPhone 实时同步回看。
3. **为什么采用标准 PWA？**
   - 决策日期：2026-11-13。
   - 理由：支持添加到手机桌面无缝全屏体验，离线可用且无须上架 App Store，完全符合独立高能小工具定位。
